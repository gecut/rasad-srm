# راهنمای واردات داده‌ها (Data Import Specification)

این مستند راهنمای استاندارد واردات دسته‌ای داده‌ها (CSV / JSON) به سامانه رساد (Rasad SRM v2) است.

---

## ۱. ترتیب وابستگی‌های واردات (Import Order)

به دلیل وجود روابط کلید خارجی بین موجودیت‌ها، واردات باید دقیقاً با ترتیب زیر انجام شود:

```
1. محدوده‌های منزل (Neighborhoods) ──┐
2. مدرسین (Teachers) ───────────────┼──> 3. کلاس‌ها (Classes) ──> 4. دانش‌آموزان (Students)
```

1. **محدوده‌های منزل (`neighborhoods`)**: بدون وابستگی خارجی.
2. **مدرسین (`teachers`)**: بدون وابستگی خارجی.
3. **کلاس‌ها (`classes`)**: وابسته به شناسه مدرس اصلی (`primaryTeacher`).
4. **دانش‌آموزان (`students`)**: وابسته به شناسه محدوده منزل (`neighborhood`) و در صورت انتساب به شناسه کلاس (`currentClass`).

---

## ۲. قالب فایل‌های CSV برای هر موجودیت

### ۲.۱. محدوده‌های منزل (`neighborhoods.csv`)

| نام ستون       | نوع داده | الزامی؟ | توضیحات و نمونه                                                                            |
| :------------- | :------- | :-----: | :----------------------------------------------------------------------------------------- |
| `name`         | متن      |   بله   | نام یکتای محدوده (مثال: `وکیل آباد`)                                                       |
| `description`  | متن      |   خیر   | توضیحات کلی محدوده جغرافیایی                                                               |
| `subDistricts` | متن      |   خیر   | محله‌ها و خیابان‌های تحت پوشش، جداشده با کاما یا ویرگول فارسی (مثال: `هفت تیر، حافظ، صدف`) |

**نمونه CSV:**

```csv
name,description,subDistricts
"وکیل آباد","محدوده بلوار وکیل‌آباد و بولوار‌های منتهی","هفت تیر، حافظ، صدف، دانشجو"
"احمدآباد","منطقه احمدآباد و خیابان‌های اطراف","راهنمایی، ملاصدرا، طالقانی"
"قاسم آباد","منطقه شهرک غرب مشهد","شریعتی، فلاحی، حجاب"
```

### ۲.۲. مدرسین (`teachers.csv`)

| نام ستون    | نوع داده | الزامی؟ | توضیحات و نمونه                                   |
| :---------- | :------- | :-----: | :------------------------------------------------ |
| `firstName` | متن      |   بله   | نام مدرس (مثال: `محمد`)                           |
| `lastName`  | متن      |   بله   | نام خانوادگی (مثال: `رضایی`)                      |
| `mobile`    | متن      |   خیر   | شماره همراه (فرمت: `09123456789`)                 |
| `status`    | انتخاب   |   بله   | وضعیت: `active` یا `inactive` (پیش‌فرض: `active`) |

**نمونه CSV:**

```csv
firstName,lastName,mobile,status
"محمد","رضایی","09151112233","active"
"علی","حسینی","09123334455","active"
"مهدی","مرادی","09351234567","active"
```

### ۲.۳. کلاس‌ها (`classes.csv`)

| نام ستون         | نوع داده | الزامی؟ | توضیحات و نمونه                                                                                          |
| :--------------- | :------- | :-----: | :------------------------------------------------------------------------------------------------------- |
| `title`          | متن      |   بله   | عنوان کلاس (مثال: `کلاس شهید چمران - دوره تابستان`)                                                      |
| `primaryTeacher` | عدد (ID) |   بله   | شناسه عددی مدرس اصلی از جدول مدرسین                                                                      |
| `capacity`       | عدد      |   خیر   | ظرفیت پیشنهادی کلاس (مثال: `25`)                                                                         |
| `status`         | انتخاب   |   بله   | وضعیت: `planned`, `active`, `completed`, `cancelled`, `transition_to_preliminaries` (پیش‌فرض: `planned`) |

**نمونه CSV:**

```csv
title,primaryTeacher,capacity,status
"کلاس شهید چمران",1,25,"active"
"کلاس شهید باکری",2,20,"planned"
"کلاس شهید همت",3,30,"active"
```

## ۳. ویژگی‌های نرمال‌سازی خودکار در هنگام واردات

سیستم واردات به صورت خودکار تغییرات زیر را روی داده‌ها اعمال می‌کند:

1. **پاکسازی کاراکترهای عربی و فاصله‌های اضافه:** تبدیل خودکار `ي` به `ی` و `ك` به `ک`، و حذف فاصله‌های اضافی در ابتدا، انتها و میان کلمات.
2. **یکدست‌سازی ارقام شماره‌های تلفن:** ارقام فارسی/عربی (`۰۱۲۳۴۵۶۷۸۹`) به ارقام انگلیسی تبدیل شده و به فرمت استاندارد کشوری نرمال‌سازی می‌شوند.
3. **تبدیل اعداد پایه تحصیلی (`grade`):** در صورت ورود ارقام فارسی (مانند `۵`)، به عدد صحیح تبدیل می‌شوند.
4. **تبدیل تاریخ‌های شمسی (`absorbedAt` و ...):** الگوهای تاریخ شمسی نظیر `1403/07/15` به صورت خودکار به لحظه استاندارد UTC بر مبنای ظهر ساعت ۱۲:۰۰ تهران تبدیل می‌گردند.
5. **تنظیم منبع ثبت:** فیلد منبع ثبت (`origin`) برای تمام رکوردهای وارداتی برابر با `'import'` قرار می‌گیرد.
